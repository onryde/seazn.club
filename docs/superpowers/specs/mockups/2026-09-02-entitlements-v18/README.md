Two constraints these files encode, both binding on implementation:

- **Mobile is designed, not shrunk.** At 320 the ticket is portrait — stub
  across the top, serial and ADMIT ONE on the short edge, horizontal tear —
  and type is set up, not down. A 320 capture that is the 1280 composition
  with smaller type is a rejection.
- **Never print a variant count** beside the sport rail. The database says
  37 and `sync:sports` says 31; neither number has been verified, so the
  rail names sports and counts nothing.

Open them directly in a browser; they are self-contained.
