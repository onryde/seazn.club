## Findings

### MAJOR

**MAJOR-1** `.github/workflows/placement-ci.yml:433-473` (with the pin `packages/scheduler/test/integration-runs-elsewhere.test.ts:72-79`) — fail-open judge.
- **Problem:** the vitest step is `continue-on-error`. The judge reads only total, passed, numFailedTests and numPendingTests, then checks that each live file's name appears in `.testResults[].name`. A file that fails to collect does appear there (`status: "failed"`, zero assertions) and counts only in `numFailedTestSuites`.
- **Proof:** a scratch two-file run where `repair-decompose-cpsat-integration.test.ts` throws at load. Vitest exited 1; the judge printed `total=4 passed=4 failed=0 skipped=0 failedSuites=1` and exited 0.
- **Why it's new here:** with one file, the old judge was safe (total 0 ⇒ red). Adding the second file opened the gap.
- **Fix:** fail on `numFailedTestSuites != 0`, and/or require each live file to have `status == "passed"` with `assertionResults | length > 0`. Extend the pin at :72-79 to assert the new clause. Mutate once: delete the clause; the pin must go red.

**MAJOR-2** `packages/scheduler/src/__tests__/live-seam-guard.ts:14-23`, `live-seam-guard.test.ts:22-24`, `placement-integration.test.ts:61-64, :234-241` — guard narrower than its name.
- **Problem:** the no-silent-greedy guard only rejects `solver_unavailable`, and its unit test pins that `solver_busy` and `verifier_rejected` pass. Two of the four live cases (:297, :393) can therefore pass on a greedy board with a live service configured.
- **Inconsistency:** the sibling live file fails the same SOLVER_BUSY through `recordSolver`.
- **Plan gap, not an implementer slip:** plan Review Focus 2 named only `solver_unavailable`.
- **Fix:** in `buildLive`, wrap `placementSolver` with `recordSolver` and call `assertSolverReached` in the `afterEach` for non-deliberate tests. For non-deliberate live boards, also treat `verifier_rejected` and `solver_busy` as failures. Flip `live-seam-guard.test.ts:22` to assert those statuses now fail. Mutate once.
