# Engine split — Phase 1 batch 1d: reverse inventory (input to the 2b plan)

Written by Task 1d-6 (plan `docs/superpowers/plans/2026-10-13-engine-split-phase1.md`, Task 1d-6; spec §5.4, R19, D32i). Tree: `feat/engine-split-1d` after `ffad021be`, batch base `0fa3b66fc`.

**What this is.** Every non-engine file that reads an engine-owned path (a file under `packages/engine/`, or `.github/workflows/mutation.yml` and the Stryker files), what it reads, how many tests depend on it, and the **planned 2b fate**. The four fates are the plan's: **M** moves to the engine repo, **I** reads from the installed package (`@onryde/seazn-engine`, i.e. `dist/` + the manifest), **D** deleted with a reason, **U** unchanged (reads a path that stays, or only names an engine path in text). A planned fate is a proposal for the 2b plan to confirm, not a ruling.

**How it was produced, and two false premises in the plan's method.**
- The plan's command (`grep -rlaE "packages/engine|mutation\.yml|stryker-" … --include=*.ts`) has two holes: it skips `.tsx`/`.mjs` files (it missed `apps/web/src/components/public-site/__tests__/player-matches.test.tsx`, a real reader) and its root list misses tests outside `__tests__` dirs (`tools/bench/lib/__tests__/`, `packages/reference/test/`). This inventory scans **every tracked test-like file outside the engine** (`.test.`/`.spec.`/`__tests__/`/`test/`/`e2e/`; `.ts .tsx .mjs .mts .js .cjs`) for the pattern plus `engine-canary|engine-pack|pack-proof|"packages", "engine"|\.\./engine/` (the last one catches a reader that climbs to the engine by a RELATIVE path and never writes `packages/engine`; the 1d review found `packages/reference/test/rule-rows.ts` that way), and keeps **non-comment** hits only. 35 files have a code hit (27 rows in Section A; the 8 others are Section B string fixtures); the other ~84 files the plan's grep returns (apps/web components, libs, server code, e2e specs, helpers) name an engine path **in a comment only** and read nothing (Section B).
- "Tests depending" is a script count of `it`/`test` blocks that contain the read or a constant derived from it (module-level helpers included where checked by hand). It is exact where a row says so and `~` otherwise.
