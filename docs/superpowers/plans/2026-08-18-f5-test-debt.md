### Root cause

`qualify()`'s own comment (line 796) states the harness only ever builds
single-source `ProgressionSpec`s. The reason isn't the spec type (it already
supports `sources: ProgressionSource[]`) — it's that `qualify()`'s own
signature takes ONE `SourceTables` object and wraps it as `[tables]` before
calling `resolveProgression`, so `shapes[1]`/`tables[1]` are always
`undefined` for a hypothetical second source. Every `switch (opts.format)`
case in `simulateDivision` (lines 847+) also only ever calls one prior
stage's `qualify()`, so no simulated division has ever fed a stage from two
different prior stages at once — the exact shape F3 shipped to production
(multi-source picker templates) has zero fuzz coverage.

- [ ] **Step 1: Widen `qualify()`'s signature**

Replace `packages/engine/src/testkit/simulation.ts:791-812`:

```typescript
function qualify(
  stageRecord: SimStageRecord,
  spec: ProgressionSpec,
  tables: readonly SourceTables[],
): EntrantId[] {
  // Multi-source aware: each spec.sources[i] resolves against tables[i].
  // shapes are safe as `{ poolKeys: [] }` per source regardless of the
  // source's real pool shape — none of rankRange/bestNth/picks (the
  // TakeRule kinds this harness emits) reads shape.poolKeys.
  const size = spec.sources.reduce((n, s) => n + progressionSize(s.take), 0);
  const shapes = spec.sources.map(() => ({ poolKeys: [] }));
  const { qualifiers } = resolveProgression(spec, shapes, tables);
  const seeds = qualifiers.map((q) => q.entrantId);
  stageRecord.qualification = { spec, seeds };
  if (seeds.length !== size) {
    throw new SimInvariantError(`qualification produced ${seeds.length} seeds, spec wants ${size}`, { spec });
  }
  if (new Set(seeds).size !== seeds.length) {
    throw new SimInvariantError(`qualification seeds not distinct`, { seeds });
  }
  return seeds;
}
```
