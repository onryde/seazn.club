## Findings

Seven. Four were found by a test or a run; three were found by reading the
tree against a premise and watching the premise lose.

### F1 (BLOCKING, fixed at `9fcd6d685`) — the sweep was by files touched, not by behaviour changed

T2's `visibilitychange`/`focus` effect was registered unconditionally on the
**always-mounted** `FixtureConsole` root. `apps/web` vitest is
`environment: "node"`, so three existing suites crashed at mount:

```
ReferenceError: document is not defined   fixture-console.tsx:552
ReferenceError: window is not defined     fixture-console.tsx:553
```

`fixture-console-forfeit-hooks`, `-person-names` and `-undo-pad-events`, 8
tests. `git blame` pins the lines to the rebased T2 commit, so this was ours
and was reachable the moment T2 landed — the rebase did not cause it. The
file's other `document` listeners (`:87`, `:1279`) survive because they sit in
child components the harness never mounts; this was the first on the root.

**Every gate we ran missed it, and none of them could have caught it.** T2's
gates were the pad-pipeline suite and the CI-wiring test. e2e does not run
vitest at all, so the PR's 10/10 green e2e could never have contradicted it.
It surfaced only from a **full** `apps/web` run (1483 files, 20438 tests) done
after the rebase for an unrelated reason. Failure classes 2 and 16 together:
the sweep was scoped to the files we had touched rather than to the behaviour
we had changed — and "mounts the fixture console" is a behaviour that 23
`apps/web` test files touch, 12 of them named for it.

Fixed by guarding on the absence of a DOM. Not a harness concession: React
never runs an effect during SSR, so "no document ⇒ no listener" is the
effect's real server behaviour, and returning states it rather than throwing.

**And the mutation reading was wrong first.** M10 (flip the `document` clause,
keep both) SURVIVED, which was read as "two guards covering for each other,
collapse to one". Collapsing to the `document` clause alone promptly reddened
5 tests. The clauses are not redundant: `forfeit-hooks` (`:90`) and
`-person-names` (`:216`) `vi.stubGlobal("document", …)` — they need it for the
child listeners — but never stub `window`, while `-undo-pad-events` stubs
neither. Each clause covers a **different suite set**, and the untouched one
legitimately absorbed the mutation. Rule 3 needs the sharper form: mutate one
guard at a time **and read WHICH suites go red**, never merely whether any do.

### F2 (fixed) — the design named one cursor, the plan named two, there were three

`use-pad-pipeline.ts` read `ledgerEvents.length` as if it were the ledger's tip
seq. §5 named the stream cursor; the plan named two. The third,
`submitHeld`, is the copy **every real v3 tap routes through** — a
brief-literal fix would have left the compounding-409 half of the defect live
on the only path a scorer actually hits. All three moved (`:1203`, `:1608`,
`:1717` at HEAD), and the reviewer swept `components/`/`app/`/`server/`/`lib/`
independently for a fourth and found none.

Reproduced red before the fix: `expected 3 to be 4` on the sparse cases with
both controls passing. The plan's one honest gap — "this defect is reasoned
from code and not yet reproduced" — closes as **confirmed**, not as a false
premise.

### F3 (fixed) — the spec the plan specified would have passed with no fix

T2's brief said to stall the pad by aborting the realtime token door. That
does not stall the pad — it **promotes** it to the 15s poll
(`use-fixture-stream.ts:21`), comfortably inside the 20s timeout the brief
wrote. The console would have refreshed via the pad, the assertion would have
gone green, and T2 would have shipped proving nothing. Failure class 3, a
guard nothing kills, authored by the plan itself.

Closed by discriminating on **cursor** instead: the console's `resync` is
always `since_seq=0` while the pad polls its own tip (observed `=1`), so
blocking the pad's cursor value blocks the pad specifically and leaves the
console's own fetch reachable. Self-guarding — if the pad ever switched to 0,
the precondition catches it.

Three of the brief's selectors were also wrong, each of which would have been
vacuous or red: `[data-testid="fixture-console"]` does not exist;
`wonBy: "home"` is refused by `kernel.ts` because `wonBy` is an entrant id;
and one rally renders `"0 — 0 (1–0)"`, so `toHaveText("1")` could never match.
The expected value is now **derived from `summary.headline` each run** rather
than typed into the test.

### F4 (fixed at `30fb29f08`) — the guard against vacuity was itself vacuous

`scripts/realtime-gate.sh` checked for the realtime clause with a bare
substring grep. In `device-links.spec.ts` the symbol appears three times — an
import at `:5`, a **prose comment** at `:477`, and exactly **one** call at
`:661`. Delete every call site and the comment alone still satisfies `grep
-qa`: the gate runs, six tests pass with nothing asserting realtime, and it
exits 0. Measured, not argued — one run printed
`OLD GUARD: SATISFIED (would have run and passed)` beside the new `EXIT=3`.

Now counts call-shaped occurrences on non-comment lines, and the pre-flight
prints the per-spec call count (**1** and **2**, not 3 and 3) on every run so
the positive direction is checked too.

### F5 (fixed at `363610b27`) — the gate confidently denied a regression it had measured

`NOT_REALTIME` was checked before `FAILED`, both set per leg with no memory of
which leg carried a verdict. One leg failing **without** a verdict (a flake in
the 8-test serial leg suffices) plus the other failing **with** one made the
gate print *"This is NOT evidence of a realtime regression, and must not be
read as one"* over a sibling log containing `no websocket ever joined this
fixture's channel`.

Failure class 6 verbatim — an absent symptom meaning *suppressed* rather than
*safe* — and worse than having no gate, because the text instructs the reader
to stop looking. Verdicts are now tracked per leg and a measured realtime
verdict outranks a sibling's unrelated failure: mixed ⇒ exit 1 naming both
legs, and exit 4 is reserved for runs where **every** failing leg was silent.

**Driven, not simulated.** A keyless server on `:3383` made the serial leg
fail with a real verdict; a watcher killed it as the second leg started. New
code → `EXIT=1 FAILED (MIXED)`; the old ordering under the same construction →
`EXIT=4`, with the suppressed verdict sitting at line 19 of its own log.

### F6 (recorded in §5) — "one-way resync" was a true clause with a false conclusion

§5 said a console score "never reaches the device-link header until the umpire
taps something". The clause it rests on is true — `device-score-pad.tsx:119`
resyncs only after its own send or its own pad's ledger change — but
`handlePadEvents` is wired as `onEvents` (`:373` → `registry.tsx:299` →
`pad-host.tsx:1575-1578`), which fires on **any** change to `pipeline.events`,
including a foreign write merged in by the poll or the socket.

Same shape as the §6b correction already recorded for `fixture-console.tsx`: a
component's resync triggers were read and the `onEvents` edge out of it was
not followed. The real causes were upstream in both directions — the
unauthenticated stream (W1) and the cursor (F2). A premise naming the wrong
file survives review because every sentence in it is true.

### F7 (recorded) — the task brief for this record was wrong about who fixed `auth`

T4's brief said §5's `auth` bullet was "FIXED by W1+W2". `git log -S` over
every member of the chain names one commit, `df892fac2` (#823, W1), and W2's
squash (`ae94280cb`, #825) touches none of those files. Small, and recorded
because it is the eighth premise in this wave to be corrected by re-pinning it
against the tree rather than inheriting it.

  T2's precondition claims "no independent path refreshes this console"; the
  slowest such path is the pad's `POLL_MS = 15_000`, and the window was a flat

  polls 1→2), which tracks the constant if it moves. **The other two windows
  are correctly flat and now say why**: both exclude a *synchronous* listener
  answer to an event dispatched a line earlier, so padding them to 15s would
  have misdescribed the mechanism rather than tightened it.

  claim ("identical spec code went 1 failed → 3 passed") had a differential
  carried across an edit to one of its two sides. Re-run with M6 — the whole
  effect deleted, the true no-fix state — and the no-fix state now fails
  **two** independent assertions where it previously failed one.
- The green e2e leg was re-run **4×** (45.6 / 49.3 / 46.9 / 51.8s), all
  EXIT=0, and the runner named the walkthrough by full title beside the setup
  projects each time — not zero tests selected.
- Green gate legs finish in ~14s against red legs at ~30s and ~24s, because

  override of its brief as an "owner ruling"; the product owner had never been
  asked. Corrected to "controller ruling (SDD)" with a note saying so. In this
  repo those are different authorities and a later reader cannot tell a real
  ruling from a confident mistake.
- **Two immutable commit messages carry claims now known to be false**, and
  are corrected in the reports rather than silently: `f3d05a046` says

  appears once. The generalisable error in the first: the constant's own file

  "cannot be obtained". Two different questions, one checked.
- **A checksum that matches nothing is worse than no checksum**, because it
  reads as verification. One recorded `shasum` turned out to be a genuine hash
  of the intermediate restore point, taken before two further edits — every
  number real, the pairing misleading. Once a restore is followed by more
  edits, the restore checksum stops being the artifact's checksum.

  mounts, and the specs fail with **no realtime message at all** — an

  exit 4, and the stale server was kept as its regression fixture.
- **Spec-only edits need no rebuild** — Playwright loads specs from source.
  Only `src/` changes need a new bundle. That halved the turnaround on the
  remaining e2e work.
